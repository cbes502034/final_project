# LLM 專題可行性研究與 Top 10 提案

一份四人、一個月、以 LLM 為主軸並須完成 Docker 部署的專題，在正式選題之前所做的可行性研究。
成果是一個純前端的報告站台，收錄經過十四階段研究流程篩選出的 **Top 10 專題提案**，
每一題都提供「不使用 Function Calling」與「使用 Function Calling」兩種版本的完整分析。

---

## 這份報告怎麼產生的

刻意**不從**「適合學生的 LLM 專題」這類關鍵字下手，也不從熱門開源專案改名。
產生順序是：

1. 先分析團隊能力與資源限制（在任何一次搜尋之前完成）
2. 把限制轉換成待調查的問題
3. 跨十八個領域搜尋現實世界存在的問題與工作流程
4. 調查這些工作目前由誰做、用什麼做、痛點在哪
5. 評估實際應用價值與商業價值
6. 逐一查證台灣**真的能下載**的公開資料與介接條件
7. 查證微調可行性、樹莓派實測效能、Function Calling 在小模型上的失敗率
8. 搜尋實際失敗案例與論文，最後才用開源專案驗證工程可行性
9. 建立 40 個候選題 → 回頭對照原始需求過濾 → 十項評分
10. **第二輪**：把搜尋問題從「大量人工閱讀」改寫成「需要人親眼看」，補搜影像方向並新增 3 個候選
11. **實務落地紅旗過濾**：刷掉「理論可行但要別人開權限才做得起來」的題目
12. 重新評分（提高實際應用與落地可行性的權重）→ 取 Top 10

所有引用編號 S1–S55 對應 `research/03-sources.md` 中實際查證過的來源。

## 站台功能

主頁只放專題本身：

- 晶片卡片牆呈現 Top 10，可依領域篩選；**卡片以「晶片有沒有接腳」表示這題需不需要樹莓派**
- **選題投票**：四人各選一題，透過 Server-Sent Events 即時同步，任何人改動其他人畫面立刻更新；被選中的卡片整張發白光
- 詳細頁依「源起 → 前提摘要 → 專案說明及分析 → 分工 → 時間規劃 → 結語」順序閱讀
- **不使用／使用 Function Calling 兩種版本可在同一頁切換，不重新載入、保留捲動位置**
- 每題附十項評分明細、樹莓派角色、Function Calling 判定、實務落地障礙與未來延展性
- 專案結構圖與流程圖為 inline SVG，採半導體與電路板語彙繪製
- 頁首章節導覽隨捲動高亮；頁面底部提供上一題／返回主頁／下一題，支援左右方向鍵
- 正文固定窄欄（約 46 個中文字一行），表格與圖另有較寬的版面
- 三段式響應式設計，手機可完整閱讀

研究過程另外收在 `#/about` 的**專案說明文件**，五個抽屜預設收合：研究方法、團隊與資源限制、
評分指標與權重、候選池處理結果、資料來源與關鍵證據。看專題不需要讀這一頁。

## 本機執行

```bash
python -m http.server 5173 --directory site
```

開啟 <http://localhost:5173>。

## 部署

兩個服務，設定見 `render.yaml`：

- **報告站台**：靜態站台，發布目錄 `site`，不需要建置指令，走 CDN 即時載入
- **選題投票**：`votes/` 下的小型服務，提供投票 API 與 `/api/stream`（SSE）；報告本身不依賴它，服務未就緒時投票面板會自行降級為輪詢

投票資料存放於 PostgreSQL；未設定資料庫時自動退回本機 JSON 檔（開發用）。
